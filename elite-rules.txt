- Arabic copy: Modern Standard Arabic, simple and direct. No slang in UI labels.
- English copy: sentence case, plain verbs, no filler.

- An action keeps one name through the whole flow (button "Send message" leads to toast "Message sent").
- Errors say what went wrong and how to fix it. They never apologize and are never vague.
- All user-facing strings live in `messages/ar.json` and `messages/en.json`. NEVER hardcode text in components.

### Placement rules

- **MUST** co-locate page-specific components in `<page>/components/` and page data in `<page>/data/`.
- **MUST** put anything used by 2+ pages in `components/shared/`.

- **NEVER** import from one page's `components/` into another page. Promote it to `shared` first.
- One component per file. File name = component name in PascalCase. Route folders are kebab-case.

## 5. Architecture rules

### 5.1 Routing
- App Router with route groups. Dynamic segments: `[locale]` and `[id]`.
- `middleware.ts` enforces the locale prefix and redirects `/` to `/{defaultLocale}/home`.
- Pages are **Server Components by default**. Add `"use client"` only when the file needs state, effects, browser APIs, or Framer Motion. Keep client boundaries as low in the tree as possible.

### 5.2 Internationalization and RTL (this is the biggest change from Imdad)
- `i18n/routing.ts` declares `locales: ["ar", "en"]`, default `ar` (assumption 2).
- `<html lang dir>` is set in `app/[locale]/layout.tsx`: `dir="rtl"` for `ar`, `dir="ltr"` for `en`.
- **MUST** use logical Tailwind utilities so layouts mirror automatically: `ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end`, `border-s`, `border-e`, `rounded-s-*`, `rounded-e-*`.
- **NEVER** use `ml-*`, `mr-*`, `pl-*`, `pr-*`, `left-*`, `right-*`, `text-left`, `text-right` for layout.
- Directional icons (arrows, chevrons) MUST flip in RTL (`rtl:-scale-x-100`).
- Use `Link`, `redirect`, `usePathname` from `i18n/navigation.ts`, never from `next/link` or `next/navigation` directly.
- Every key exists in both `ar.json` and `en.json`. Missing keys are a build-blocking bug.
- Numbers, phone numbers, and emails inside Arabic text MUST render correctly (wrap in `dir="ltr"` spans where needed).
- Every new page MUST be visually checked in **both** languages before it counts as done.

### 5.3 Styling system
- Colors, radii, shadows, and spacing come from CSS custom properties in `globals.css`, mapped in `tailwind.config.js`.
- **NEVER** write raw hex or `rgb()` values in components. Use tokens (`bg-primary`, `text-body`, `border-edge`).
- If a token is TBD, stop and ask. Do not pick a color.
- Merge classes with `cn()` from `lib/utils.ts`. Never build class strings by hand concatenation.
- Mobile-first. Breakpoints: base, `sm`, `md`, `lg`, `xl`. Test at 360px, 768px, 1280px.
- Use one consistent border-radius scale tied to hierarchy (not one radius for everything).

### 5.4 Design principles (so the revamp does not look templated)
- Build from the brand and the real content. Do not fall back on a generic SaaS look: identical rounded cards, soft grey shadows under everything, gradient washes as decoration.
- Spend boldness in **one** place per page (hero or one key section). Keep everything around it quiet.
- Body text line length under 80 characters. Arabic body text needs generous line-height.
- Structural devices (numbering, eyebrows, dividers) only when they carry meaning. Number markers only for real sequences.
- **NEVER** use ALL-CAPS tracked labels above every heading, a "→" on every button, or accent-colored single words in headlines as a habit.
- Use real or plausible content, not lorem ipsum. Copy follows section 2.4.

### 5.5 Animation
- Presets live in `lib/animations.ts` (`fadeInUp`, `staggerContainer`, `scaleIn`, `heroTextReveal`, ...). Components import presets, they do not define their own variants inline.
- Use motion sparingly: one orchestrated hero moment plus meaningful interactions (menus, accordions, modals). **Not** a fade-up on every section and hover lift on every card.
- Counters and scroll reveals trigger once (`viewport={{ once: true }}`).
- **MUST** respect `prefers-reduced-motion`.
- Animate `transform` and `opacity` only. Never animate layout properties.
- In RTL, horizontal slide variants MUST mirror direction.

### 5.6 State and API
- Redux store via `configureStore`. Only keep truly global state there (UI preferences, auth if added). Local UI state stays in components.
- All HTTP goes through the singleton `ApiService.ts` (Axios). No ad-hoc `fetch` or new Axios instances in components.
- `axiosBaseQuery.ts` is the adapter if RTK Query is used.
- Interceptors inject the auth token and `lang` header. Any `localStorage` access MUST be guarded with `typeof window !== "undefined"` (SSR safety).
- API base URL comes from `app/config/environment.ts`, which reads env vars. Never hardcode URLs.
- Errors from the API are normalized by `ExtractValidationErrors.ts` and shown in the form, not swallowed.

### 5.7 Forms
- React Hook Form + Zod schema + `@hookform/resolvers/zod`. The schema is the single source of validation.
- Validation messages come from `messages/*.json`, not from Zod defaults.
- Use shared `InputField` and `TextArea`. Do not restyle inputs per page.
- Every input has a visible label, an error state, and a disabled/submitting state.
- Success and failure feedback use React Hot Toast with the wording rules from section 2.4.

## 6. Code quality rules

- TypeScript **strict**. No `any`, no `@ts-ignore` without a comment explaining why.
- Props are typed with an explicit `interface` or `type`. Shared types live in `types/`.
- No unused imports or dead code. `npm run lint` and `npm run build` MUST pass with zero errors before any task is reported done.
- Do not leave `console.log`. Use `app/services/logger.ts`.
- Static datasets (projects, partners, solutions) are typed arrays in `data/`. Components receive data via props or imports from `data/`, never inline literals inside JSX.
- Use `next/image` for all images with explicit `width`/`height` or `fill` + `sizes`, and meaningful `alt` text in the active locale. Use `next/font` for fonts. Use `next/link` (through `i18n/navigation`) for internal links.
- Do not put secrets in the repo. Env vars that reach the browser use the `NEXT_PUBLIC_` prefix, nothing else does.

### Accessibility (quality floor)
- Visible keyboard focus on every interactive element.
- Color contrast meets WCAG AA for both languages.
- Semantic HTML: one `h1` per page, ordered headings, `nav`, `main`, `footer` landmarks.
- Menus, modals, and accordions use Headless UI / Radix so keyboard and screen-reader behavior is correct.
- Icon-only buttons have `aria-label`.

### Performance and SEO
- Metadata per page via `generateMetadata`, localized (title, description, Open Graph, `alternates.languages`).
- Hero video: compressed, `muted playsInline`, with a poster image and a mobile fallback.
- Leaflet maps load with `next/dynamic` and `ssr: false`.
- Lazy-load below-the-fold sections and heavy libraries (Recharts, Leaflet).

## 8. Do / Don't summary

**Do**
- Read the relevant existing files before editing and follow their patterns.
- Reuse shared components and tokens before creating new ones.
- Check both languages and 3 screen sizes after every UI change.
- Keep changes small and scoped to the task.
- State assumptions in one line when something is ambiguous, then proceed.

**Don't**
- Don't add a dependency, change a major version, or restructure folders without asking.
- Don't hardcode strings, colors, URLs, phone numbers, or nav links.
- Don't use physical (left/right) Tailwind utilities for layout.
- Don't invent brand values (colors, fonts, copy claims, stats, client names). Mark them TBD.
- Don't copy the old site's text or images verbatim without the owner confirming they are final. Rewrite and improve.
- Don't leave a task with failing lint or build.

---

## 9. Workflow for Claude Code

1. **Plan:** for any new page, list the sections, components, data shape, and message keys in a few lines before coding.
2. **Build:** tokens first, then shared components, then page sections.
3. **Verify:** `npm run lint`, `npm run build`, then check `/ar` and `/en` at 360 / 768 / 1280.
4. **Report:** a short summary: files changed, assumptions made, anything left TBD.
